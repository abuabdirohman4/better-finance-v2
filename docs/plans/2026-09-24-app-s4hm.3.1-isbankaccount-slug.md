# app-s4hm.3.1 — Fix `isBankAccount` dead slug comparison

**Bead:** `app-s4hm.3.1` (hub beads, label `befin`). Mode B (direct): 1 code file + 1 doc file, ~2 lines.

## Goal

`isBankAccount(accountTypeSlug)` in `src/lib/accountVisuals.ts` compares against the
slug `"atm"`. That slug was renamed to `"bank"` by migration
`supabase/migrations/20260723_rename_account_types.sql` (bf-vgh, 2026-07-23). Since then
`isBankAccount` **always returns `false`** — no account ever gets the superscript
currency treatment (`formatCurrency(amount, "superscript")`), regardless of its type.

This is a pre-existing bug, already surfaced (not fixed) during the bf-7m3 audit — see
`docs/plans/2026-09-24-bf-7m3-edit-account-type.md` line 20: *"compares to `\"atm\"`, a
slug renamed to `\"bank\"` in bf-vgh, so it currently never matches (pre-existing bug)"*.

## Confirmed facts (read before editing)

- **Current DB slugs** (per `seed_defaults_for_new_user`, `supabase/migrations/20260723_rename_account_types.sql`):
  `cash`, `bank`, `ewallet`. There is no `"atm"` slug left in the database — the migration
  renamed existing rows (`UPDATE ... SET slug='bank' WHERE slug='atm'`) and the seed
  function for new users already inserts `'bank'` directly.
- **Only one place** compares a slug literal to `"atm"`: `src/lib/accountVisuals.ts:86`.
  Grep confirms (`grep -rn '"atm"' --include='*.ts' --include='*.tsx' .` outside
  `node_modules`) — no other code, test, or script does this comparison.
- `scripts/migrate-sheet.ts` also contains the string `"ATM"` (lines 38, 43, 331, 428,
  430, 710) but those are **spreadsheet column names** (`Wallet | ATM | Platform`), not
  `account_types.slug` values — grep for `slug` in that file shows no slug-based ATM
  comparison. **Do not touch this file.**
- No test file exists for `accountVisuals.ts` or `isBankAccount` (`find . -iname
  "*accountVisuals*"` → only the source file). No test changes needed.
- `isBankAccount` has exactly two callers, both already reading `account.account_type_slug`
  (an `AccountRow` field, `src/db/queries/accounts.ts:24`):
  - `src/app/(app)/accounts/_components/AccountCard.tsx:14`
  - `src/app/(app)/accounts/[id]/_components/CalculationBalanceCard.tsx:29`

  Neither caller needs to change — they pass the slug through unmodified. Only the
  comparison target inside `isBankAccount` is wrong.

## Step 1 — Fix the comparison

**File:** `src/lib/accountVisuals.ts` (lines 84–87)

Before:
```ts
/** Akun yang di-render pakai formatCurrency superscript (bank ATM). */
export function isBankAccount(accountTypeSlug: string): boolean {
  return accountTypeSlug === "atm";
}
```

After:
```ts
/** Akun yang di-render pakai formatCurrency superscript (tipe Bank). */
export function isBankAccount(accountTypeSlug: string): boolean {
  return accountTypeSlug === "bank";
}
```

(Comment reworded from "bank ATM" to "tipe Bank" since the account type is now literally
named "Bank", not "ATM" — avoids reintroducing the stale name.)

## Visual impact (expected, not a regression)

Before this fix, **no account** ever rendered with superscript currency formatting
(`AccountCard.tsx` balance bar, `CalculationBalanceCard.tsx` balance rows) because
`isBank` was always `false`. After this fix, any account whose `account_type_slug ===
"bank"` (i.e. type "Bank" — BCA, Mandiri, BNI, etc. in the seed data) will switch to the
`formatCurrency(..., "superscript")` rendering path (smaller decimal digits via `<sup>`)
in both:
- `src/app/(app)/accounts/_components/AccountCard.tsx` (balance bar, ~line 68-76)
- `src/app/(app)/accounts/[id]/_components/CalculationBalanceCard.tsx` (`formatBal`, ~line 29-40)

This is the **intended** fix, not a side effect to guard against — the superscript path
already existed and was clearly built for bank accounts; it was just unreachable. No
other account type (Cash, E-wallet) is affected — they continue to render with the plain
`formatCurrency(amount)` path.
