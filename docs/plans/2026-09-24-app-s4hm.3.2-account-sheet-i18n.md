**Bead:** `app-s4hm.3.2` (hub beads, label `befin`). Mode B (direct): 3 files (1 component
+ 2 i18n catalogs), ~20 lines total.

## Goal

`src/app/(app)/accounts/_components/AccountBottomSheet.tsx` has literal Indonesian (and a
couple of literal English) strings instead of `t()`/`tc()` calls. Per `AGENTS.md` i18n
rule: **every user-facing string must go through `t()`**, catalogs `en.json`/`id.json`
must have identical keys (enforced by `src/i18n/__tests__/messages.test.ts`), and new
keys go into `en.json` first (type-safety augmentation in `src/global.d.ts` derives from
it).

The file already imports and uses `useTranslations`:
```ts
const t = useTranslations("accounts");
const tc = useTranslations("common");
```
So no new import is needed — only replacing literals with `t("key")` / `tc("key")` calls
and adding the missing keys.

## Open questions

1. **`placeholder="0"` on the balance number input (line 269) — left untouched.**
   Recommendation: **leave as-is.** Grepped the codebase
   (`grep -rn 'placeholder="0"' src/app/(app)`) — two other numeric inputs
   (`WalletDenominations.tsx:141`, `BudgetBottomSheet.tsx:218`) use the same bare `"0"`
   literal, uninternationalized, project-wide. It's a digit, not language-specific text,
   so it's consistent with existing convention to leave it a plain literal rather than
   invent a one-off key that every other numeric input in the codebase lacks.

2. **`accounts.balanceLabel` = "Balance" is a new key rather than reusing
   `accounts.currentBalance` ("Current Balance").** Recommendation: **keep them
   separate.** `currentBalance` is already used as a distinct display heading elsewhere
   (e.g. `CalculationBalanceCard.tsx`) with a specific "current vs reality" meaning;
   reusing it here for a plain editable-field label risks a wording mismatch if that
   other usage's copy changes later for unrelated reasons.
